# Hobart Premium Meat Co. — Processing & Inventory System

A frontend prototype of a meat-processing inventory system for a Hobart (Tasmania) butchery
that breaks down livestock and wholesales cuts to restaurants, pubs, hotels and retail butchers.

Built to be demoed to a client before any backend exists. Every screen is functional — you can
add, edit and delete real records and watch the dashboard, stock levels and reports respond.

> **Deployment target:** `inventory.shakilahmed.tech`

---

## What it does

| Area | What's covered |
|---|---|
| **Dashboard** | Head processed, carcass in, saleable out, boning yield, revenue. Day / custom / weekly / monthly views. Per-animal yield analysis table, cut production, stock, top accounts, wastage, low-stock and expiry alerts. |
| **Livestock Intake** | Consignments from farms, saleyards and service abattoirs — head count, live weight, carcass weight, dressing %, cost, invoice and NVD number. |
| **Processing Runs** | Boning-room breakdown of each batch into individual cuts, in kilograms **and piece counts** (drumsticks, cutlets, steaks…), plus trim / bone / waste. One-click "auto-fill standard yield" from the catalogue's yield profile. Creates stock lots automatically. |
| **Inventory** | Stock by cut, lot-level traceability (lot code, cold room, produced date, use-by), cold-room capacity view, manual adjustments, low-stock and expiry flags. |
| **Wastage & Trim** | Trim, bone and avoidable loss by reason and species, with written-off value and yield-loss %. |
| **Orders** | Wholesale orders with line items, delivery runs, printable dockets with GST. Moving an order to *Packed* draws stock out of the cold rooms (FIFO). |
| **Customers / Suppliers** | Full account records with lifetime value, spend and per-species supply. |
| **Reports** | Eight report types over any date range, each exportable to CSV and printable. |
| **Settings** | Company details, alert thresholds, JSON backup / restore, demo-data controls. |

### The two questions the client asked first

1. **"How many drumsticks / steaks / cuts do we have?"** — Inventory ▸ *By cut* shows kilograms **and**
   piece counts for every portioned line. Processing ▸ *Top cuts produced* and Reports ▸ *Cut production
   report* show the same for anything produced in a period.
2. **"How many animals did we process, and how much meat did each one give?"** — Dashboard ▸
   *Animals processed* and *Yield analysis per animal* break head count, live kg/head, carcass kg/head,
   saleable kg/head, dressing % and boning yield % down by species. The same sits in
   Reports ▸ *Production & yield by species*.

## Stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS v4** — light and dark theme, deep-red brand accent
- **Recharts** for charts, **lucide-react** for icons
- **Zustand** + `persist` middleware → browser `localStorage` (key `hpm-inventory-v1`)

No backend, no database, no API keys. Everything runs in the browser.

## Demo data — and how to remove it

All sample records are generated by **one file**: `src/data/demo-seed.ts`.
It produces ~6 months of deterministic trading history (intake batches, processing runs, stock lots,
orders and wastage) relative to today's date, so the demo always looks current.

**To go live with real data, pick any one of these:**

1. Open `src/data/demo-seed.ts` and set `export const DEMO_DATA_ENABLED = false;`
2. Delete `src/data/demo-seed.ts` and its single import in `src/lib/store.ts`
3. In the running app: **Settings ▸ Data Management ▸ Clear all data**

Nothing else in the codebase depends on it.

`src/data/catalog.ts` is **not** demo data — it holds the real cut catalogue (46 cuts across beef,
lamb, goat, pork and poultry), the cold rooms, the per-species yield profiles and the default company
settings. Keep it and edit it to match the client's actual product list.

## Project layout

```
src/
  app/                 one folder per screen (App Router)
  components/
    charts/            Recharts wrappers — stacked bars, area, line, ranked bars
    layout/            sidebar, top bar, theme toggle, navigation
    ui/                buttons, inputs, modals, data table, stat tiles, toasts, badges
  data/
    catalog.ts         cut catalogue, yield profiles, cold rooms   ← real configuration
    demo-seed.ts       sample trading history                      ← delete to go live
  lib/
    types.ts           the domain model
    store.ts           Zustand store + all CRUD actions            ← swap for a real API here
    analytics.ts       every derived figure on the dashboard and reports
    dates.ts           date ranges, presets, day/week/month bucketing
    csv.ts, format.ts  CSV export and en-AU number/currency formatting
```

### Adding a backend later

`src/lib/store.ts` is the only place that touches data. Every screen calls actions such as
`upsertOrder`, `setOrderStatus`, `upsertRun`. Replace the bodies of those actions with API calls
(and swap the `persist` middleware for a fetch layer) and the UI keeps working unchanged.

## Notes for the demo

- The bell in the top bar aggregates low stock, lots nearing use-by, and overdue deliveries.
- Every table supports search, sorting, pagination and CSV export.
- `Print` on the Dashboard, Reports and order dockets produces a clean print layout.
- Theme follows the system by default; the toggle in the top bar overrides it.
- Layout works down to phone width.

All company, supplier and customer names in the demo data are fictional.
